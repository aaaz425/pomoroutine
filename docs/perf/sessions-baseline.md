# 전체 기록 조회 기준선

웹이 전체 sessions를 받는 구조를 바꾸기 전 측정값, 작업 후 같은 스크립트로 다시 측정해 비교

## 환경

| 항목 | 값 |
|---|---|
| 측정일 | 2026-10-18 |
| DB | 로컬 Supabase 도커 스택, Postgres 17.6 |
| 기기 | Apple M2 |
| 웹 | 측정용 프로덕션 빌드, 3100번 포트 |
| 브라우저 | Playwright Desktop Chrome |
| 부하 도구 | k6 2.3.0 |

- 네트워크 지연이 없는 로컬 측정이라 시간은 데이터셋 간 상대 비교용, 핵심 지표는 바이트와 요청 수
- 로컬 Kong은 응답을 압축하지 않음 — 본문 크기는 로컬 응답 그대로, gzip은 본문을 gzip으로 압축한 크기로 운영 전송량 추정치

## 데이터셋

`pnpm perf:seed`로 생성, 시드 고정이라 다시 실행해도 같은 데이터

| 계정 | 기록 | 기간 | 행 크기 |
|---|---|---|---|
| `perf-100@example.com` | 100건 | 17일 | 66KB |
| `perf-1k@example.com` | 1,000건 | 179일 | 680KB |
| `perf-10k@example.com` | 10,000건 | 1,675일 | 6.7MB |

- 하루 0~12건, 10%는 기록 없는 날
- 카테고리 5개, 작업 20개, 10%는 미분류
- 집중 구간 평균 4.5개, 메모는 절반 정도 30~200자
- 방해 태그 0~3개, 집중 평점 70% 입력, 자유 모드 15%

## k6 — 엔드포인트별 응답

`pnpm perf:k6`, 단일 사용자 50회 반복

| 데이터셋 | 조회 | 중앙값 | p95 | 본문 크기 |
|---|---|---|---|---|
| 100건 | 전체 조회 | 3.4ms | 18.3ms | 85KB |
| | 이번 달 범위 | 2.3ms | 3.5ms | 85KB |
| | 페이지 20건 | 1.5ms | 1.9ms | 14KB |
| | RPC 요약 | 1.6ms | 2.7ms | 1.7KB |
| 1천 건 | 전체 조회 | 8.3ms | 15.7ms | 850KB |
| | 이번 달 범위 | 2.1ms | 2.7ms | 76KB |
| | 페이지 20건 | 1.6ms | 2.3ms | 13KB |
| | RPC 요약 | 2.1ms | 3.0ms | 1.7KB |
| 1만 건 | 전체 조회 | 69.2ms | 116.3ms | 8.4MB |
| | 이번 달 범위 | 2.3ms | 3.7ms | 106KB |
| | 페이지 20건 | 1.6ms | 1.7ms | 14KB |
| | RPC 요약 | 9.2ms | 18.8ms | 1.7KB |

- 1만 건 전체 조회를 10명이 동시에 5회씩 보내면 중앙값 748.6ms, p95 1328.5ms
- 전체 조회만 기록 수에 비례해 커지고, 범위와 페이지 조회와 RPC는 기록 수와 거의 무관
- 100건은 전부 이번 달 안이라 범위 조회 크기가 전체 조회와 같음

## Playwright — 화면 흐름

`pnpm --filter web perf:flow`, 데이터셋마다 5회 실행한 중앙값

흐름은 통계 진입 → 기간 탭 4개 전환 → 기록 탭 이동 → 화면 이탈 후 복귀 → 1분 타이머 완료 후 기록 저장

- 표시 시간은 단계 시작부터 데이터가 들어간 요소가 보일 때까지
- 완료 시간은 마지막 Supabase 응답 후 0.8초간 요청이 없을 때까지
- 중복은 같은 흐름에서 메서드, URL, 본문이 같은 요청이 다시 나간 횟수

### 단계별 요청

| 단계 | 요청 |
|---|---|
| 통계 진입 | settings, tasks, categories, 전체 sessions, RPC 요약 2회 |
| 기록 탭 진입 | sessions 첫 페이지 30건 |
| 화면 복귀 | tasks, categories, settings, 전체 sessions, sessions 첫 페이지 |
| 기록 저장 | sessions insert |

## 관찰

- 전송량의 99%가 전체 sessions 조회 2회 — 통계 진입과 화면 복귀
- 화면 복귀 요청 5개가 모두 중복, 1만 건이면 복귀 한 번에 8MB, gzip 1.2MB
- 통계 진입 시 RPC 요약이 2번 호출됨 — sessions가 빈 배열일 때와 조회 완료 후, `useEffect([sessions])` 의존 때문
- 기간 탭 전환은 요청이 없지만 1만 건 전체 탭은 다른 탭보다 2배 이상 느림, 클라이언트 집계 비용으로 추정
- 기록 탭은 첫 페이지 23KB만 받는데도 1만 건에서 882ms, 전체 sessions를 쓰는 인사이트와 날짜 표시 계산이 원인으로 추정
- 기록 저장 후에는 재조회 없음

## 재측정

```bash
supabase start
pnpm perf:seed
pnpm perf:k6
pnpm --filter web perf:flow
```

- 원본 결과는 `perf/results/`에 저장, 커밋하지 않음
- 빌드를 건너뛰려면 `PERF_SKIP_BUILD=1`, 일부만 돌리려면 `PERF_DATASETS=10k PERF_RUNS=1`
